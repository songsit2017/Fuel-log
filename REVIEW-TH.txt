----------------------------------------------------------------
✅ สิ่งที่ยืนยันว่ายังทำงานถูกต้อง (ของเดิมที่เคยแก้ไว้ไม่มีอะไรหลุดไป)
----------------------------------------------------------------
- บั๊ก localStorage (window.store พิมพ์ผิด) — ยังคงแก้ไว้ถูกต้อง
- ปุ่ม × / ยกเลิก ในฟอร์ม — ยังเป็น type="button" ไม่บันทึกเอง
- ปั๊มใกล้เคียง auto-refresh เวลาเข้าแท็บหน้าแรก/เติมน้ำมัน — ทำงานถูกต้อง
- Firestore rules exists() guard กันการอ่านรถที่ยังไม่เคยสร้าง — ยังอยู่ครบ
- ปุ่มเลือกกล้อง/แกลเลอรีอันใหม่ (media picker) ก็ใส่ type="button" ถูกต้อง
  ตั้งแต่แรก ไม่เจอปัญหาซ้ำแบบเดิม (แสดงว่าจุดนี้ระวังไว้แล้ว)

----------------------------------------------------------------
🐛 บั๊กที่เจอใหม่ และแก้ให้แล้วในไฟล์ที่แนบ
----------------------------------------------------------------

1) CSV export ของรายการ "ค่าใช้จ่ายอื่นๆ" คอลัมน์เลื่อนผิดตำแหน่ง
   ไฟล์: app.js (ฟังก์ชัน exportCSV)
   อาการ: แถวของค่าใช้จ่าย (ไม่ใช่น้ำมัน) มีช่องว่างเกินมา 1 ช่อง ทำให้พอเปิด
   ใน Excel/Sheets แล้ว "หมวดหมู่" ไปโผล่ใต้หัวคอลัมน์ "รายการ", "รายการ"
   ไปโผล่ใต้หัวคอลัมน์ "ปั๊ม", และ "หมายเหตุ" หลุดไปเป็นคอลัมน์ที่ 17 ซึ่งไม่มี
   หัวข้อรองรับเลย (ทดสอบยืนยันด้วยข้อมูลจริงแล้ว) — แก้โดยตัดช่องว่างที่เกิน
   มาออก 1 ช่อง ตอนนี้ทุกคอลัมน์ตรงกับหัวตารางแล้ว

2) แฟล็ก "พลาดการบันทึกครั้งก่อน" ไม่ถูกใช้จริงในการคำนวณ
   ไฟล์: app.js (ฟังก์ชัน metrics)
   อาการ: มีช่องให้ติ๊ก "พลาดการบันทึกการเติมครั้งก่อนหน้า" ในฟอร์ม และแสดง
   คำเตือนในรายการ แต่ตัวเลข "อัตราสิ้นเปลืองเฉลี่ย (กม./ลิตร)" กลับยังเอา
   ช่วงที่ติ๊กไว้นี้ไปคำนวณรวมด้วยอยู่ดี ทั้งที่ระยะทางระหว่างรอบนั้นน่าจะ
   เป็นผลรวมของหลายรอบเติมจริง (ไม่ใช่แค่รอบเดียว) ทำให้ตัวเลขเพี้ยนได้ —
   แก้ให้ข้ามช่วงที่ติ๊กไว้ออกจากการคำนวณค่าเฉลี่ยแล้ว เหมือนที่ Fuelio ทำ

3) แนบรูปในรายการแรกสุด (ก่อนเคยซิงก์) อาจอัปโหลดไม่ผ่าน
   ไฟล์: app.js (ฟังก์ชัน uploadAttachedPhotos) + storage.rules
   อาการ: เหมือนบั๊ก "สร้างรหัสเชิญ" ที่เคยแก้ไปก่อนหน้านี้เป๊ะ แต่เกิดกับ
   Storage แทน Firestore — ถ้าผู้ใช้แนบรูปใบเสร็จ/เรือนไมล์ตั้งแต่รายการ
   แรกสุดโดยที่ยังไม่เคยกด "ซิงก์ข้อมูลยานพาหนะ" มาก่อนเลย กฎความปลอดภัย
   ของ Storage จะพังตอนเช็คสิทธิ์เพราะเอกสารรถยังไม่มีอยู่จริง ทำให้อัปโหลด
   รูปไม่สำเร็จ — แก้ 2 จุด: (ก) โค้ดจะสร้างเอกสารรถให้ก่อนอัปโหลดเสมอ
   (ข) เพิ่มการเช็ค exists ในกฎ Storage เหมือนที่ทำกับ Firestore rules ไว้

4) โฟลเดอร์ mobile/www เป็นสำเนาเก่าที่ไม่ตรงกับเว็บล่าสุด
   ไฟล์ mobile/www/app.js และ mobile/www/index.html ในไฟล์ zip ที่ส่งมา
   ยังเป็นเวอร์ชัน 6.1 (ไม่มีช่องผู้ขับขี่/วิธีชำระเงิน/เหตุผล/แนบไฟล์เพิ่ม
   ที่เพิ่งเพิ่มใน 6.2) เหตุผลคือมีสคริปต์ mobile/scripts/sync-web.mjs
   ที่ต้องรันเพื่อคัดลอกไฟล์เว็บล่าสุดเข้า mobile/www ก่อนสร้าง APK เสมอ
   (คำสั่ง npm run android:sync จะรันให้อัตโนมัติอยู่แล้วถ้าทำตาม README)
   แต่ถ้าลืมรันขั้นตอนนี้ก่อน build จะได้แอป Android ที่ล้าหลังกว่าเว็บ
   — ผมซิงก์ไฟล์ mobile/www ให้ตรงกับเว็บล่าสุดในชุดที่แนบให้แล้ว ไม่ต้อง
   กังวลสำหรับรอบนี้ แต่ครั้งต่อไปที่แก้เว็บ อย่าลืมรัน
   `cd mobile && npm run android:sync` ก่อน build APK ทุกครั้ง

📝 หมายเหตุเล็กน้อย (ไม่กระทบการทำงาน)
----------------------------------------------------------------
- sw.js เก็บเลขเวอร์ชันของไฟล์ (?v=5.0.5) ที่เก่ากว่าเวอร์ชันจริง (6.2.0)
  แต่ไม่กระทบอะไรเพราะกลไก cache ใช้ network-first แยกต่างหากอยู่แล้ว —
  แก้ให้ตรงกันเพื่อความเรียบร้อยแล้วเช่นกัน
- OCR อ่านบิลใช้ Tesseract.js (ฟรี ไม่ต้องมี API key) ซึ่งดีตรงไม่มีค่าใช้จ่าย
  แต่ความแม่นยำในการอ่านภาษาไทยจากใบเสร็จจริงจะสู้ AI OCR แบบ Vision model
  ไม่ได้ ควรตรวจข้อมูลที่ดึงมาก่อนบันทึกทุกครั้ง (แอปมีช่องให้แก้ไขอยู่แล้ว)

สรุป
----------------------------------------------------------------
โค้ดโดยรวมอยู่ในเกณฑ์ดีมากแล้วครับ ไม่มีบั๊กร้ายแรงระดับที่เจอในเวอร์ชันก่อนๆ
(syntax error, localStorage ไม่ทำงาน, ฟอร์มบันทึกเอง) จุดที่เจอรอบนี้เป็น
บั๊กแบบ "เฉพาะกรณี" (edge case) มากกว่า — ยังใช้งานได้ปกติในสถานการณ์ทั่วไป
แต่ควรอัปเดตไฟล์ที่แนบให้ทับของเดิมเพื่อความถูกต้องครบถ้วนครับ
